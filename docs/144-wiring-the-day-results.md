# Wiring the docked day into the world: results

Scores `docs/143`'s six predictions. All six pass. What cannot be scored
here is how the game itself carries the day; §3 says what a session at
RimWorld has to look at.

## 1. What was built

- **`SaveText`**, the game's save format for the whole docked state,
  generated by `economy_lab/state_codegen.py` beside the JSON codec from
  the same field list. A double is its sixteen hex digits, and every
  collection carries its count. It is schema 4, and an older save loads
  with no economy and builds one.
- **`EconomyWorldComponent`** builds the docked economy on the first day
  the world has a faction region: 200 commodities, one region per
  faction, the world's `persistentRandomValue` as the seed. The day is
  seventeen phases, one a tick: the profiles, a build-and-refuse phase,
  then the fifteen docked phases. The build phase is always in the list,
  so a save taken mid-day resumes at the same phase whether or not the
  economy existed when it began.
- **The tab** shows the economy's status and each region's consumer
  goods: the fund's final goods and the workers' staple, in
  worker-days, silver and price over value.

## 2. Predictions

**1. The save format round-trips every state the fixtures hold: passes,
on the first compile.** All 76 states round-trip. Three corrupted saves
(truncated, extended, and with a string token altered) are refused.

**2. Saving and loading after every phase changes nothing: passes.** All
four run fixtures end bit-identical when the state is encoded and
decoded after every one of their 6,300 phases. Through the component,
a three-faction world saved and reloaded after every tick for three
days ends with the same economy as the world that never was.

**3. The battery's state encodes to between 0.5 and 2 MB: passes.** It
is 0.99 MB, and a save and load takes 13.6 ms. A six-region world will
be about 3 MB of save text.

**4. The docked day under Mono is bit-identical to the day under .NET 8:
passes.** Under Mono 6.8, the docked day built from each fixture's seed
reproduces all four of the laboratory's end states, including the
battery's 30 days at 1,600 producers. A three-faction world in the
component equals the docked economy run directly. This holds on this
Linux machine, whose `exp` and `pow` both runtimes take from one libm.
Windows and macOS remain untested.

**5. A docked day under Mono costs under three times .NET 8: passes
easily.** The battery's day is 24.5 ms under Mono and 25.4 ms under
.NET 8 in the same whole-run harness.

**6. The component compiles against the unedited facade: passes.** It
builds with no errors or warnings, and `Economy.Drive`'s existing
scenarios pass beside three new ones: 44 checks, no failures. The
scenarios' schema expectations moved from 3 to 4. One scenario had
ticked ten ticks past the start of a day, which completed a one-phase
day and not a seventeen-phase one, so it now ticks a hundred.

## 3. What only the game can answer

- **The tick budget.** A three-region world's first day costs 161 to
  290 ms in total, with one phase at 106 to 188 ms. That phase is
  building the economy and the first compile of the code. At steady
  state, production alone costs 9 ms a day at two regions and 27 ms at
  ten under .NET 8, all in one tick. That is a visible hitch once a
  game day at 60 frames a second. Splitting production across ticks is
  the next design if the game shows it.
- **The save in a real game**, including Mono's `Scribe` with a
  multi-megabyte string.
- **The tab**, which has never been seen. Twenty-odd rows per region
  may need a scroll view at ten regions.
- **The assemblies.** `rimworld/economy_mod/1.6/Assemblies/` still holds
  the build from before this work. `verify.py` says so, and the mod has
  to be rebuilt against RimWorld's own assemblies.
