# How to check this is not fabricated

Written for a skeptical reader — in the first instance Ian Wright, who
would be right to assume the worst about a pile of confident prose
generated by a language model.

**Start here:**

```
git clone <repo> && cd <repo>
python -m economy_lab.verify_wright          # ~60s, 13 checks
```

No dependencies. No install step. Pure standard-library Python; the only
non-stdlib imports anywhere in `economy_lab/` are its own modules. Each
check **recomputes** a figure and compares it to what a cited document
claims, and a `FAIL` means a document is wrong.

## 1. Sixty seconds: things a fabricator could not produce

The verifier's first two sections are chosen because they are
**closed-loop** — they have right answers that do not depend on trusting
us.

- **Money conservation.** The model is a closed accounting system:
  N actors, M = 100,000 coins, and every rule only ever moves coins
  between actors and the market pool. Over 20 seeds × 180 months the
  total stays within **7.4e-10** of 100,000. Output generated to look
  plausible does not conserve a quantity to nine decimal places across
  360,000 stochastic transfers.
- **Bit-identity.** `size_exponent=1.0` reproduces Wright's rule and
  `size_exponent=0.0` reproduces the size-neutral ablation, *exactly* —
  same money vector, same employment vector, same pool, same firm sizes.
  This is binary and unfakeable, and `docs/118` §2 explains the float
  reasoning that makes it hold (dividing by `members ** (1 - β)` rather
  than multiplying by `members ** (β - 1)`, which double-rounds and
  differs on 23% of draws).
- **The estimators recover planted answers.** `power_law_fit` returns
  **2.505** on data drawn from an α = 2.5 power law. On data drawn from
  a *lognormal*, `likelihood_ratio` returns **−2.62, favouring the
  lognormal** — the check that matters most, because it is the
  instrument behind our most critical claim about Wright's own result
  (`docs/114`). Integer durations score KS **0.0144** against a
  geometric null and **0.4310** against a continuous exponential, which
  is the entire content of `docs/113`'s correction to fact 5.

This validates the **measurement stack independently of the model**. A
reader can reject our economics entirely and still see that the fitting
code works.

## 2. Twenty minutes, and only you can do it: is it your model?

**Everything downstream is conditional on one file.**

```
economy_lab/social_architecture.py     # 584 lines
```

That is the whole transcription: nine rules, three parameters. It is
deliberately small and readable, methods are named for your rules
(`_select` SR1, `_hire` H1, `_spend` E1, `_sample` M1, `_fire` F1,
`_pay` W1, `month` 1M, `year` 1Y), and the docstrings quote your prose
where a choice was interpretive. Two places we made a judgement call and
flagged it in the code:

- `_fire` tests against `m_a`, the firm's **money holdings**, not its
  month's revenue. Your §2.7 prose admits both readings; the docstring
  says so.
- `_sample`'s size neutralisation counts **owner plus staff**, because
  that is how many times a firm samples per month under SR1.

**This is the crux and we cannot check it.** No amount of verification
downstream rescues a transcription that is not your model. We could not
commit your paper alongside it for copyright reasons, which is exactly
why this section exists.

## 3. Two minutes: the audit trail says predictions came first

The project's discipline is that a **design document with numbered
predictions is committed before the code that tests them**, and git
enforces the ordering:

```
git log --diff-filter=A --format="%h %ad %s" --date=short -- docs/118*.md docs/119*.md
  1e55e0e  2026-09-15  Measure the size-exponent sweep: docs/119
  94cf091  2026-09-15  Design the size-exponent sweep: docs/118
```

The bands in `docs/118` §4 and the seven predictions in §5 were written
into the repository before the sweep existed.

**The strongest evidence is that they failed.** Fabricated research
confirms itself; this record does not:

| document | outcome |
|---|---|
| `docs/109` | prediction 1 failed immediately — 640 of 1024 cells threw |
| `docs/116` | prediction 3 failed **backwards**: linearity carries Laplace growth, not contingency |
| `docs/119` | prediction 4 failed decisively — the condensation we predicted does not happen |
| `docs/120` | **`docs/119`'s own headline conclusion withdrawn two commits later** |

`docs/120` is the one to read if you want to know whether this record is
honest. It retracts a published finding because the band that produced
it was one-sided for a two-sided target — an error that was visible
without any data, and is recorded as such rather than quietly amended.

## 4. Twenty minutes: re-run the expensive things

Nothing here is a long computation. One 300-month run is **2.9 seconds**.

```
python -m economy_lab.verify_wright --full      # + the 200-run 2x2, ~3 min
python -m economy_lab.m1_ablation   out.json 50 # docs/116, ~4 min
python -m economy_lab.size_exponent out.json 50 # docs/119, ~12 min
python -m unittest discover tests               # the full suite
```

The raw records behind the published tables are committed, so a reader
can re-derive a table without re-running anything:
`economy_lab/size_exponent_results.json` (1000 runs) and
`economy_lab/grid_results.json` (1024 cells).

## 5. Where a skeptic should push hardest

Listed because we would rather point at them than have them found.

1. **Transcription fidelity** (§2). The single point of failure.
2. **`docs/120` §2 uses a band chosen after seeing the data.** We say so
   in that document. The load-bearing argument there is §4, which uses
   no bands at all — only your two reported numbers and a relative
   squared loss — and reaches the same conclusion. Read §4, not §2.
3. **`power_law_fit` caps the `x_min` search at 200 candidates.**
   Continuous data makes every point a candidate and the exact search
   was O(n × unique). The cap is an approximation and it is not
   independently validated against a reference implementation.
4. **Below β ≈ 0.9 the firm-size fit spans less than one octave**, so
   the exponents in that region of `docs/119`'s table are not
   measurements. `docs/119` §2 says so; the table still prints them.
5. **The income-tail result is our weakest** (`docs/114`): not rejected
   in only 46 of 100 seeds, lognormal undetermined in 99 of 100.
6. **One test fails and it is not ours.**
   `tests/test_port_fixtures.py::test_the_committed_fixtures_are_current`
   fails on `scale_647_day3` by one ULP. It predates this work and fails
   with every change of ours stashed. It concerns the RimWorld side of
   the repository, not the Wright side.

## 6. What verification cannot reach

None of this is evidence about real economies. We have not touched
empirical data at any point. The activity is closer to checking a
proof's lemmas than to economics: reimplement a published model, then
ask which of its lines produce which of its advertised results. That can
catch mis-attribution — `docs/116` and `docs/119` §5 both do — and it
can never move a model toward truth.

`docs/117` §7 states the caution we hold ourselves to: *"we docked with
Wright" must not become "our model is validated"*, because that chains
his model matching stylized facts to ours matching his, and neither link
carries the weight.
